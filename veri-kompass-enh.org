* veri-kompass enhanced
./veri-kompass目录里有个emacs脚本，是我根据github已有脚本稍微做了些改进。
现在希望继续做改进，主要是针对以下缺点不足：
- 跟踪驱动和负载线时需要更直观智能，目前不够直观，智能，请参考synopsys的工具verdi
- 还是关于跟踪驱动和负载线，在跨模块时，如果信号名没有改变的，直接跨模块追踪到源
  头，而不是停留在模块边界上
- 给出其它相关的收效大的功能建议

** 目标与使用场景
优先服务 RTL debug 中的信号来源/去向追踪；层级理解作为辅助能力。交互保持 Emacs
键盘优先：常见情况直接跳转，存在多个候选或歧义时打开可预览的结果 buffer。

** 功能路线图
*** Phase 1: 信号追踪闭环 MVP
- 建立更清晰的 trace candidate 表示，记录方向、位置、代码片段和追踪原因。
- 改进 =C-c d= / =C-c l= 的多候选结果窗口，上下移动时同步预览，=RET= 确认。
- 支持同名信号跨模块自动穿透：例如子模块 =input clk= 连接父模块 =.clk(clk)= 时，继续向父层追踪。
- 增加 trace jump 历史：确认跳转后可回退/前进，便于 peek 后回到原学习代码。
- 保持无外部依赖，先覆盖常见 module、port、assign、实例 named port connection。

*** Phase 2: Verdi 风格但 Emacs 原生的结果体验
- 候选结果显示方向、层级路径、文件行号和代码片段。
- 追踪路径可解释每次跨模块跳转的原因。
- 对低置信度或歧义结果给出提示，不静默跳错。

*** Phase 3: 层级理解增强
- hierarchy buffer 支持按实例名/模块名搜索，并展示更清晰的模块、实例、文件位置。
- 增加当前信号穿过哪些 instance boundary 的辅助视图。
- 增加跳到当前 module、跳到当前 instance module、返回上一追踪位置等命令。

*** Phase 4: 高收益分析功能
- 轻量 fanin/fanout 分析，列出直接来源和直接使用点。
- 常见端口连接检查：未连接、同名连接、可能方向不匹配。
- 解析缓存和重新索引命令，减少重复扫描。
- Debug 历史，记录最近追踪过的信号和路径。

** 当前实现计划
- 不修改脚本文件名，继续使用 =veri-kompass/veri-kompass.el=，因为它匹配 package 名称和 =(provide 'veri-kompass)=。
- 第一轮实现聚焦 Phase 1 的 driver 追踪：同名 input 跨父层继续追踪，以及统一候选预览窗口。
- load 追踪先复用统一候选窗口，后续再扩展跨子层 fanout。
- 新增 ERT 覆盖：同名跨模块 driver 追踪、多候选窗口 marker 预览、加载与字节编译。
